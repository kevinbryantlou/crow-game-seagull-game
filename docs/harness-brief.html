§0 Why there is a harness at all

It exists because of one bug. Early on, 100 of 351 meshes rendered pure black and shipped that way, because the game had never actually been looked at. The cause was a single missed return value — tint() hands back a non-indexed clone for indexed geometry, so a caller that ignores it leaves vertexColors: true on a mesh with no colour attribute. Every unit test passed. The block was a third black.

Both scripts exist to close that gap from opposite ends, and the division between them is the whole design: smoke asks questions that have answers in the data, and shoot asks questions that only have answers on a screen.

The convention that matters more than either script When a bug is found, turn it into an assertion rather than just fixing it. Almost every check described here exists because something real broke. That is why the list is so specific and so strange — it is a scar map, not a test plan.

§1 smoke — the one that never draws

npm run smoke. About two seconds, no browser, no GPU, no renderer. It imports the real game modules under Node with a twenty-line stub of document — just enough canvas for the one place that builds a texture — and then runs the actual physics, collision and level code as plain three.js maths.

That constraint is deliberate and it is why the file is worth having. Anything it can check, it checks in two seconds with no flake, no timing and no rendering. So the rule for what belongs here is: if it can be answered without pixels, it must be.

What it covers

  • Pure logic suites — money spelled out in words, the end-of-run rank ladder, saved progress, the sky ramp, the HUD's position filter, and the pianist's rotation. These live in their own modules (words.js, rank.js, save.js) precisely so they can be tested without a DOM.
  • Every level-design rule, via audit-level.mjs — 73 checks, run once per entry in LEVELS. That per-level loop is the single most valuable thing in the harness, and §3 is about why.
  • A simulated minute of every block: the crow, every human, every bird, stepped at a fixed 60 Hz. It catches NaN, falling through geometry, walkers deadlocked against walls, and birds standing on decks that do not exist.

Things it found that no amount of reading would

  • A crow that could enter the fountain at three headings out of 180 and never get out — the basin was twelve boxes approximating a circle, and they met only at their corners.
  • A dollar bill inside a noticeboard, because the ledge's collider sat where the board was rather than where the ledge mesh was. The 0.12 m the ledge stands proud is the entire clearance that bill has.
  • A 4.6 m lamppost standing exactly on the one sightline a coin had to the camera.
  • Two patrol waypoints inside solids, each by less than half a metre, both invisible in the source.

§2 audit-level — the contract every block signs

This is the middle of smoke, extracted into its own file when the second block existed. The numbers it closes over — the goal, the water's shape, the nest's footprint — come from the level rather than from a literal, so a rule written for one block is enforced on all of them.

That last property is where most of its value comes from. Rule 11 was written for the roofline and caught a real defect on level 1 the same day. The coplanar-face rule was written for the wharf's flickering boat and immediately found a fifth instance on the shipped lobby clock — the object that block banks on.

The rules, in the order a level meets them

RuleWhat it actually prevents
Nest landing ≥ 2× the nest footprintBanking happens under pressure. The last obstacle should never be a pixel-accurate landing.
Nothing overlaps the nestA wheel's spokes laid eight brass bars across the twig ring. It samples triangle edges, not bounding boxes — a torus's box covers its own hole.
No two pickups within a beak-lengthThe beak takes the nearest, so closer than 1.2 m is one ambiguous target, not two.
Nothing built inside the waterRelaxed for the wharf to a declared exemption — and the escape test got stronger in the same edit to pay for it.
No pickup buried, none hidden from the cameraA raycast along the one sightline the game ever uses. The camera never rotates, so visibility is a fixed property of position.
Everything takeable carries a glintThe game's only "you can take this" signal. There is no outline shader.
Every volume the crow can enter, it can leaveA grid across the whole basin, four input patterns, from a full bar and an empty one.
Nobody stands or walks through solidsSpawns and patrol legs, checked against the real collision code.
A chase can get round every large solidCannot be authored — shooing steers straight at a crow that can stand anywhere. It has to be pathing.
No climb longer than 9 m unbroken60% of a full stamina bar, because nobody arrives at a climb with a full bar.
Everything rests on a deck that existsUnfalsifiable on a flat block; the easiest mistake in the file once there are four.
Nothing shoves the crow > 0.55 m in a frameA clipping report made falsifiable: every collider with air under it, eight headings, three heights.
Decals stack, and no two are coplanarIdentical depth is a coin flip per pixel. polygonOffset cannot fix it — it nudges both equally.
No two solids share a horizontal face planeThe newest. Invisible in source, because every number involved is the correct height for that part.
The nest platform is a flight from everything elseAlso new. Adjacency is a property of a pair, and every line of a level file describes one object.

§3 shoot — the one that draws

npm run shoot, with npm run dev in another shell. Roughly four minutes. It launches headless Chrome with software WebGL (SwiftShader), loads the real page, plays the real game, and writes 18 PNGs into shots/.

It fails on any console error or failed request, which is the cheapest and most valuable thing it does. Beyond that it splits into two kinds of work:

Behaviour, in the real engine

Things that need a running game rather than a simulated one. It can place the crow anywhere via window.__game — dev builds only — and then assert what happens: that a swimming crow can take the bottle floating in the harbour; that the whole of a nest platform is a floor, edges included; that all six legs of the wharf's intended flight path land on a half-empty bar; that trading auto-equips; that a croissant dropped on the mezzanine moves nobody, because birds do not use stairs. It also swaps levels eight times through the menu and asserts the GPU gets its memory back.

Pixels, and only three numbers of them

This is the part worth being precise about, because it is the harness's real boundary. Of the 18 frames it writes, four are measured, and on those it computes exactly three things over the lower 58% of the frame:

  • median luminance — must clear duskMedianFloor (48)
  • 5th-percentile luminance — must clear duskShadowFloor (24)
  • average RGB — only to assert blue beats red, i.e. that shade is still violet

Those three numbers have done a great deal of work. They caught a lawn that was the darkest thing on screen, a navy runner that no amount of lamps could rescue, a road darker than the grass in front of it, and a ninth lamppost that bought two points of median and cost four of 5th percentile. They are also the whole of what any frame is tested for.

Two harness bugs worth knowing about, because both printed real numbers The day was hardcoded. shoot computed "60% of the day" from a literal 18 minutes while the test session was 60 seconds, and measured four identical frames at t=1. A harness must ask the game how long the day is.

Four blocks of five were photographing dusk before the lights came on. The ramp takes ~8 s and its clock resets whenever the day is wound back below the trigger; the long settle sat on the middle sample, which is only past the trigger on one block. So the final frame was caught 700 ms into an eight-second fade. It passed for years because four blocks are bright enough unlit.

§4 What neither script can see

The harness captures composition faithfully and asserts nothing about it. A frame is checked for brightness, not for whether it looks right. Everything below passed a full green run and was caught by a person:

FaultWhy the numbers did not move
A flickering wheelhouse roofTwo coplanar faces of near-identical brightness. Swapping which wins changes the median by nothing.
Two seams at the harbour mouthSame — a hairline of near-identical colour.
A lamp post hovering 0.8 m off the groundPerfectly lit either way. It is a position, and no rule measured that position.
A lighthouse plinth overhanging its wallValid geometry, fine luminance, simply wrong-looking.
Three floor grids at three spacingsEvery line was a legal, correctly stacked decal. The set was the problem.

And two of those are worse than merely unmeasured. Z-fighting is decided per pixel per frame by depth precision, so a still may show it or may not, and the same scene screenshots differently twice. The flickering roof was invisible in every frame that was read and unmissable the moment the camera moved. A still cannot show a thing that only exists between stills.

This is exactly why CLAUDE.md says read the PNGs: the harness writes evidence it is not able to interpret. The honest summary of the division of labour is that the scripts prove the level is correct, and only a person can tell you it is good — or that it is quietly shimmering.

The one gap with an obvious fix, not yet built A short video capture, or two frames of the same scene diffed against each other, would catch z-fighting mechanically — it is the one fault class that is defined by changing between frames. Everything else on that list needs an eye.

§5 The cheats, and the three tripwires on each

Three constants at the top of main.js, all null in normal play. They exist because some things cannot be checked at full speed: TEST_TRADE_PAYOUT makes one trade clear the goal, TEST_SESSION_SECONDS shortens the day so a full dusk fits in a minute, and TEST_TIME_OF_DAY pins the light so one hour of the evening can be walked around.

Any of them shows a red TEST MODE badge, prints a banner in smoke, and logs a startup warning — three independent tripwires, and the banner matches any TEST_ prefix so a fourth cheat is covered automatically. shoot additionally refuses to run while the clock is pinned, because every dusk sample would otherwise photograph one hour and report it as three. A green run with no dusk coverage is worse than a red one.

One consequence worth stating for anyone verifying a deploy: the TEST MODE strings are always compiled into the bundle and only fire when a constant is non-null. So grepping a production bundle for them reports a false alarm every time. Load the page and read #testmode.hidden instead.

§6 Using it

constantly
npm run smokeTwo seconds, no browser. Run it after every edit — it is cheap enough that there is no reason not to.
milestones
npm run shootFour minutes, needs npm run dev alongside. Then read the PNGs — that is not optional, it is the half of the job the script cannot do.
before shipping
shoot against the deployed bundleBuilt from a detached worktree, served Vercel-style at the no-slash URL. That run has no window.__game, so it exercises the shipped code path — and the no-slash form is the one that catches relative asset paths 404ing.

Two failure modes to recognise rather than debug. A run where every dusk sample reports a median of exactly 40 is a frozen loading screen — that is #16332a, the loading card's own colour — and it means the page never booted; re-run it. And wall-clock timing on a machine also running a browser game is not trustworthy: identical scenes have measured a 4× spread, once reporting a median above its own p90. Draw calls and triangle counts are deterministic; milliseconds are not.
